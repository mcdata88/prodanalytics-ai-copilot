## Top 3 Revenue Drivers — Voice of Customer

### 1. RBAC / SSO Granularity ($12.42M Impacted ARR)
- **Customer Pain:** Enterprise security and IT teams are blocking wider rollout and new seats because roles are only admin vs read-only. They also need SCIM provisioning and SSO group-to-role mapping to meet policy, and they want to restrict access to data that contains PII by team or business unit.
- **Representative Quote:** *"Audit requires us to restrict access to production data by business unit. Current roles are too coarse."* (`TKT-1030`, Enterprise, $2.51M ARR)
- **PM Recommendation:** Ship scoped custom roles (team/service/data-type permissions) plus SCIM and SSO group mapping as one platform-wide capability, not per product. This removes a seat-expansion blocker across $12.4M of ARR, and $3.83M of it renews within 90 days.

### 2. OpenTelemetry Native Ingestion ($11.42M Impacted ARR)
- **Customer Pain:** Platform teams are standardizing on OpenTelemetry and will not deploy another proprietary agent. Today, OTLP data loses resource attributes when it passes through the vendor collector.
- **Representative Quote:** *"We are standardising on OpenTelemetry. Please support native OTLP ingestion without the proprietary agent."* (`TKT-1019`, Enterprise, $2.49M ARR)
- **PM Recommendation:** Build native OTLP endpoints for traces and metrics that preserve OTel semantic conventions. Very little of this ARR renews soon ($0.07M), so treat it as an **expansion** bet, especially for APM adoption, rather than a retention fix. Sequence it after the renewal-heavy themes.

### 3. Compliance Framework Coverage ($8.85M Impacted ARR)
- **Customer Pain:** Auditors want evidence mapped to CIS, SOC 2, PCI and HIPAA from Cloud Security posture findings, and some customers need custom frameworks for internal controls.
- **Representative Quote:** *"Please add CIS and SOC 2 benchmark packs to Cloud Security posture checks - auditors keep asking for mapped evidence."* (`TKT-1049`, Enterprise, $2.30M ARR)
- **PM Recommendation:** Prioritize exportable, framework-mapped compliance reports (CIS and SOC 2 first, then PCI and HIPAA). This theme has the **largest 90-day renewal exposure at $4.89M**, and it fits the Cloud Security Enterprise growth seen in this week's WBR.

## Method & Caveats
- **Classification:** 92 of 92 in-scope tickets were classified by the ordered regex taxonomy in the skill. **0** needed a judgment call. The 3 out-of-scope `question` tickets were how-to requests (agent changelog, API key rotation, Terraform provider) and would have been Unclassified anyway. No new theme reached the 3-ticket threshold. [Q1, Q2]
- **Ranking sensitivity:** The order depends on the weighting you choose:
  - By **90-day renewal ARR**: Compliance ($4.89M) > RBAC ($3.83M) > **Log Overage ($3.69M)** > Cost Attribution ($2.60M).
  - By **ticket volume** or **at-risk accounts**: Log Overage ranks **#1** (22 tickets, 16 of 22 accounts At Risk or Critical). That matches the −18% Mid-Market Log Management ingestion drop in this week's WBR.
  - **Read:** RBAC and OTel are the biggest long-term revenue levers. Log Overage is the most **urgent retention** risk, because many smaller accounts are actively reducing usage now. A pricing or packaging fix (retention tiers, budget caps) probably costs less engineering than the platform features above, so run it in parallel and do not let it wait in the ARR-ranked queue.
- **Dedup rule:** ARR is summed over a deduplicated theme × account set. `SUM(DISTINCT current_arr)` was cross-checked and gives the same totals on this snapshot, but it would silently undercount if two accounts shared an ARR value.
- **Data limits:** These are ticket-based demand signals only. Sales-call notes, community requests and churn surveys are not in the warehouse.

## Query Appendix

Governance came from `get_metric_definitions()` (reporting calendar: as-of = `MAX(week_start) + 7 days`) and `list_schema()`.

**Q3 — Revenue-weighted ranking** · 7 rows
```sql
WITH cal AS (SELECT MAX(week_start) + INTERVAL 7 DAY AS as_of FROM weekly_product_usage),
t AS (
  SELECT ticket_id, account_id, product_name, raw_text,
    CASE
      WHEN regexp_matches(lower(raw_text), 'overage|retention|cold tier|budget cap|drop rules|pre-ingest|log bill') THEN 'Log Overage Pricing & Retention Tiering'
      WHEN regexp_matches(lower(raw_text), 'opentelemetry|otel|otlp') THEN 'OpenTelemetry Native Ingestion'
      WHEN regexp_matches(lower(raw_text), 'cost attribution|chargeback|cost center|cost breakdown|monitoring bill|attribute observability spend') THEN 'Custom Cost Attribution'
      WHEN regexp_matches(lower(raw_text), 'rbac|sso|scim|permission|roles|restrict access') THEN 'RBAC / SSO Granularity'
      WHEN regexp_matches(lower(raw_text), 'compliance|soc 2|pci|hipaa|cis |auditor') THEN 'Compliance Framework Coverage'
      WHEN regexp_matches(lower(raw_text), 'alert|pager|noise|dedup|threshold') THEN 'Alert Noise Reduction'
      WHEN regexp_matches(lower(raw_text), 'dashboard|timeout|load time|performance') THEN 'Dashboard Performance'
      ELSE 'Unclassified' END AS theme
  FROM support_tickets WHERE ticket_type IN ('feature_request', 'complaint')),
ta AS (SELECT DISTINCT theme, account_id FROM t),
acct AS (
  SELECT ta.theme, a.*,
    (a.renewal_date >= cal.as_of AND a.renewal_date < cal.as_of + INTERVAL 90 DAY) AS renew90
  FROM ta JOIN accounts a USING (account_id), cal),
arr AS (
  SELECT theme, COUNT(*) AS accounts, SUM(current_arr) AS impacted_arr,
    SUM(current_arr) FILTER (WHERE renew90) AS renewal_arr_90d,
    COUNT(*) FILTER (WHERE health_status IN ('At Risk', 'Critical')) AS at_risk_accts
  FROM acct GROUP BY theme),
seg AS (
  SELECT theme, arg_max(arr_tier, tier_arr) AS top_segment
  FROM (SELECT theme, arr_tier, SUM(current_arr) AS tier_arr FROM acct GROUP BY ALL) GROUP BY theme),
prod AS (SELECT theme, mode(product_name) AS product_area, COUNT(*) AS tickets FROM t GROUP BY theme)
SELECT RANK() OVER (ORDER BY impacted_arr DESC, renewal_arr_90d DESC) AS rnk,
  arr.theme, product_area, tickets, accounts, impacted_arr, COALESCE(renewal_arr_90d, 0) AS renewal_arr_90d,
  at_risk_accts, top_segment
FROM arr JOIN seg USING (theme) JOIN prod USING (theme)
ORDER BY rnk;
```

**Q4 — Representative quote per theme (highest-ARR account)** · 7 rows
```sql
-- reuses CTE t from Q3
SELECT theme, arg_max(ticket_id, a.current_arr) AS ticket_id, arg_max(a.arr_tier, a.current_arr) AS arr_tier,
       MAX(a.current_arr) AS arr, arg_max(raw_text, a.current_arr) AS quote
FROM t JOIN accounts a USING (account_id) GROUP BY theme;
```
